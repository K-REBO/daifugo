# 2. コアシステム

このセクションでは、LispDaifugoEngine の中核をなすシステム群について詳しく解説します。

## 2.1. ゲームエンジン (`daifugo-game-engine`)

ゲームエンジンは、ゲーム全体のライフサイクルと状態を管理する中心的なコンポーネントです。主な責務は以下の通りです。

- **ゲームの初期化**: プレイヤーの作成、デッキのシャッフル、カードの配布など、ゲーム開始前の準備を行います。
- **ターンの管理**: 現在のプレイヤーを追跡し、次のプレイヤーにターンを渡す処理を担当します。
- **ゲームの進行**: プレイヤーからのカードプレイやパスといったアクションを受け付け、ゲームロジックを呼び出して状態を更新します。
- **ゲームの終了判定**: 勝利条件（手札が空になるなど）をチェックし、ゲームを終了させます。

### 2.1.1. ゲーム状態 (`game-state`)

ゲームの状態は `game-state` 構造体で管理されます。この構造体には、以下のような情報が含まれます。

- `players`: ゲームに参加しているプレイヤーのリスト。
- `current-player`: 現在のターンを持つプレイヤーのID。
- `field`: 現在場に出されているカードのリスト。
- `deck`: デッキに残っているカードのリスト。
- `turn-direction`: ターンの進行方向（時計回りまたは反時計回り）。
- `revolution-p`: 革命が起きているかどうかのフラグ。
- `logs`: ゲームの進行ログ。

### 2.1.2. 主要な関数

- `(create-game player-count)`: 新しいゲームを作成し、初期化します。
- `(start-game game-state)`: ゲームを開始します。
- `(play-card game-state player-id cards)`: プレイヤーがカードを出します。
- `(pass-turn game-state player-id)`: プレイヤーがパスします。
- `(game-over-p game-state)`: ゲームが終了したかどうかを判定します。

## 2.2. カードシステム (`daifugo-card-system`)

カードシステムは、ゲームで使用されるカードに関連するすべての機能を担当します。

- **カードの表現**: `card` 構造体で、ランク（3, J, Aなど）、スート（スペード、ハートなど）、強さを表現します。
- **デッキの管理**: `(create-deck)` で標準的な54枚のデッキを作成し、`(shuffle-deck)` でシャッフルします。
- **カードの比較**: `(compare-cards card1 card2)` で、2枚のカードの強さを比較します。

## 2.3. プレイヤーシステム (`daifugo-player-system`)

プレイヤーシステムは、ゲームに参加するプレイヤーを管理します。

- **プレイヤーの表現**: `player` 構造体で、ID、名前、手札、階級（大富豪、富豪など）を管理します。
- **プレイヤーの作成**: `(create-players player-count)` で、指定された人数のプレイヤーを作成します。
- **手札の操作**: `(add-card-to-hand player card)` や `(remove-card-from-hand player card)` で、プレイヤーの手札を操作します。

## 2.4. ゲームロジック (`daifugo-game-logic`)

ゲームロジックは、大富豪の基本的なルールと判定を担当します。

- **役の判定**: `(is-valid-pair cards)`、`(is-valid-sequence cards)` などで、提出されたカードが有効な役かどうかを判定します。
- **カード出しの妥当性検証**: `(validate-card-play cards field revolution-p)` で、現在の場に対してカードが出せるかどうかを検証します。
- **強度比較**: `(hand-stronger-p hand1 hand2 revolution-p)` で、2つの手札の強さを比較します。
