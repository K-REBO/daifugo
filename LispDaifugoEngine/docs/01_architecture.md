# 1. アーキテクチャ

## 1.1. 設計思想

LispDaifugoEngine は、**コンポーネントベースアーキテクチャ** を採用しています。これにより、システムの各機能が独立したモジュールとして開発・管理され、高い再利用性と拡張性を実現しています。

主要な設計原則は以下の通りです。

- **関心の分離 (Separation of Concerns)**: ゲームの各要素（カード、プレイヤー、ルール、ゲーム進行）を独立したシステムとして分離し、それぞれの責務を明確にしています。
- **データ駆動 (Data-Driven)**: ゲームの状態やルールは、コード内にハードコーディングするのではなく、データ（構造体や設定ファイル）として管理されます。これにより、柔軟なカスタマイズが可能になります。
- **イベント駆動 (Event-Driven)**: ゲーム内で発生する出来事（カードプレイ、パス、勝利など）は、イベントとして通知されます。これにより、各コンポーネントが疎結合に連携できます。

## 1.2. 主要コンポーネント

エンジンは、以下の主要なコンポーネント（Lisp パッケージ）で構成されています。

| コンポーネント | 説明 |
| :--- | :--- |
| **`daifugo-game-engine`** | ゲーム全体の進行を管理するメインエンジン。ゲームの開始、終了、ターンの進行などを担当します。 | 
| **`daifugo-card-system`** | カードの作成、デッキの管理、カードの強さの計算など、カードに関連するすべての機能を担当します。 | 
| **`daifugo-player-system`** | プレイヤーの作成、手札の管理、状態（階級など）の追跡を担当します。 | 
| **`daifugo-game-logic`** | カードの提出が有効かどうかの判定、役の判定（ペア、階段など）、カードの強さの比較など、ゲームの基本ロジックを担当します。 | 
| **`daifugo-rule-engine`** | 8切りや革命といった、ゲームのルールを動的に適用するためのエンジンです。 | 
| **`daifugo-event-system`** | ゲーム内のイベントを管理し、コンポーネント間の通信を仲介します。 | 
| **`daifugo-game-logger`** | ゲームのデバッグやテストを支援するための、高機能なロギングシステムです。 | 

## 1.3. ディレクトリ構造

ソースコードは `src/` ディレクトリに、役割ごとに整理されています。

```
src/
├── core/         # ゲームの核となるシステム
├── rules/        # 各種ルール
├── events/       # イベントシステム
├── api/          # 外部連携用API
├── utils/        # ユーティリティ関数
└── testing/      # テスト用ツール
```

この構造により、コードの見通しが良くなり、保守性が向上しています。
