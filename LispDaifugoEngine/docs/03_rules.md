# 3. ルールエンジン

LispDaifugoEngine の大きな特徴の一つは、柔軟なルールエンジンです。このエンジンにより、ゲームの基本ロジックを変更することなく、様々なローカルルールやカスタムルールを動的に追加・削除することができます。

## 3.1. ルールエンジンの役割

ルールエンジン (`daifugo-rule-engine`) は、ゲームの特定のイベント（例：カードがプレイされた時、ターンが終了した時など）にフックし、追加のロジックを実行します。これにより、標準のゲームフローに影響を与えることなく、ルールのバリエーションを実現します。

### 3.1.1. ルール構造体 (`rule`)

各ルールは `rule` 構造体で定義されます。この構造体には、以下の情報が含まれます。

- `name`: ルールの一意な名前（例：`:8-kiri`）。
- `trigger`: ルールが発動する条件を判定する関数。この関数はゲームの状態とイベントのコンテキストを引数に取り、ルールを適用すべきかどうかを返します。
- `effect`: ルールが発動した時に実行される関数。この関数はゲームの状態を直接変更することができます。
- `description`: ルールの説明。
- `priority`: ルールの優先度。複数のルールが同じイベントで発動する場合、優先度の高いルールから順に適用されます。

### 3.1.2. ルールの登録と解除

- `(register-rule rule)`: 新しいルールをエンジンに登録します。
- `(unregister-rule rule-name)`: 登録されているルールを解除します。

## 3.2. 実装されているルール

以下は、LispDaifugoEngine に実装されている、または実装が予定されているルールの例です。

- **8切り (`8-kiri`)**: 8のカードを出すと、場がクリアされ、プレイヤーは再度カードを出すことができます。
- **革命 (`kakumei`)**: 同じ数字のカードを4枚以上同時に出すと、次回のゲーム終了までカードの強さが逆転します。
- **都落ち (`miyako-ochi`)**: 大富豪のプレイヤーが次のゲームで最初に負けた場合、自動的に大貧民になるというペナルティルールです。
- **スペ3返し (`spade3-return`)**: JOKERに対してスペードの3を出すことで、JOKERの効果を打ち消すことができる特殊なルールです。
- **縛り (`suit-binding`)**: 同じスートが連続して出された場合、後続のプレイヤーも同じスートのカードしか出せなくなるルールです。

これらのルールは、`src/rules/` ディレクトリに個別のファイルとして実装されており、必要に応じて読み込まれ、ルールエンジンに登録されます。
